# Desktop Agent Driver Contract Audit

本审计以 `integrate-desktop-agent-home` 已完成的产品 owner 为事实来源。后续实现只能从这些 owner
投影中立 facts，不得创建第二套 conversation/session/configuration authority。

| Driver requirement                         | Existing authoritative owner                                        | Current evidence                                                                                                           | Contract gap                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Application/Window/View/Workspace identity | Desktop shell bootstrap and `DesktopAgentBridgeRuntime`             | sender-derived `applicationInstanceId`, `windowId`, Project/Workspace/View identity, renderer/view epoch and connection id | 缺少 fixture-only facts envelope、launch mode、application disposal result                   |
| Sender-bound public input path             | preload `OpenNekoDesktopAgentBridge` and shared host controller     | bootstrap, typed message send/subscribe, route coverage audit and stale identity rejection                                 | 缺少固定 automation controls、accepted operation correlation 和 terminal wait contract       |
| Conversation/Pi Session identity           | `DesktopAgentWorkspaceRuntime` and `NodePiConversationAuthority`    | Workspace/Conversation/branch/Pi Session/writer epoch evidence                                                             | 缺少跨 reload/restart 的 bounded checkpoint/restore facts                                    |
| Turn/run identity and durability           | `DesktopAgentTurnOperation` / `DesktopAgentTurnResult`              | Pi turn/run identity, durability, authoritative Pi Session/SQLite/projection path                                          | 结果未通过公开 Desktop bridge 投影为 versioned facts；缺少 dropped/truncated 语义            |
| Model/runtime configuration                | `ConfigManager`, model policy resolver and Pi provider registration | turn 前解析模型策略和 LLM 参数                                                                                             | 缺少 requested/effective typed snapshot、逐维度 source/scope/restart 语义和稳定 digest       |
| Prompt/Skill/Tool receipts                 | system prompt builder, Node Pi Skill Host and Tool registry         | 各 owner 能生成 Prompt、Skill catalog 和 Tool registry                                                                     | 缺少 turn-scoped identity/fingerprint receipt 及 no-fallback evidence                        |
| Permission                                 | `PiToolConfirmationRegistry` and Pi permission policy               | sender-bound confirm route and exact pending Tool confirmation                                                             | 缺少 decision/tool-call identity receipt、denied/stale/mismatched facts                      |
| Timeline/projection                        | `ConversationProjectionStore` and attachment server                 | authoritative snapshot/patch、projection version、read-only connection view                                                | 缺少 terminal revision/checkpoint 与 evaluation facts 的 identity correlation                |
| Usage/diagnostics                          | Pi result/events and Desktop error projection                       | runtime diagnostics and部分 token/context data可由 owner 读取                                                              | 缺少 allowlisted usage、bounded diagnostic、redaction 和 required-fact completeness contract |
| Disposal                                   | bridge/controller/workspace/AppHost composition                     | 显式 detach/dispose，错误以 `AggregateError` 暴露                                                                          | 缺少每样本 lease/handle/process cleanup facts 和 cleanup-failure outcome                     |

因此首个真实 case 仍必须保持 `infrastructure-blocked`，直到公开 Desktop automation control/facts
契约、有效配置投影和完整生命周期证据全部接通。DOM 文本、普通日志、Main/Pi 直接调用或 mock
输出均不能填补以上缺口。
