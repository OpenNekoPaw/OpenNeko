# W7 Evaluation Driver Blocker

## Current Finding

The original driver blocker is resolved. The Pi-era Desktop driver has been deleted and production
`runCase` now assembles the public DSH Desktop driver. Canonical facts, model sequence, Timeline,
Tool/Automation, process order, permission identity and reports consume DSH Session projections;
queue/send-now paths are retired rather than translated.

Model configuration is also executable through the public sender-bound product operation. It
requires the exact visible Conversation and an idle DSH Session, selects one advertised Composer
model and verifies both the effective model and unchanged DSH Turn count. The former running-Turn
future-configuration path is rejected by the schema.

## Remaining Blockers

Pi-era Draft binding replacement, pre-Session Draft input and synthetic rejection facts have been
deleted from the Evaluation schema, workflow, driver, evidence adapter and affected cases. Ordinary
first submit remains canonical through the visible Composer. Application lifecycle uses canonical
DSH operations and retained facts, and every requested lifecycle check has an exact matching
`desktop-lifecycle` hard gate; its real Desktop + Provider matrix remains unexecuted. DSH inbox is
explicitly excluded while Desktop has no public product operation and rc.7 cannot retain pending
inbox across owner release. Visible approval, application reopen, domain Tool, hidden batch and
pixel evidence also require real Desktop + Provider execution before release acceptance.

## Forbidden Shortcut

- Do not restore the deleted Agent launch/automation bridge or `confirmTool` contract.
- Do not create a direct ACP/DSH runtime runner outside the complete Desktop session owner.
- Do not translate DSH Session/turn/Tool-call identities into Pi `runId`/`branchId` shapes.
- Do not count key-free schema tests, injected mock drivers or direct ACP calls as Agent behavior evidence.

The current deterministic result is 45 files / 314 tests and 26 suites / 65 cases. It proves harness
and canonical-path readiness only, not real Agent behavior or release acceptance.
