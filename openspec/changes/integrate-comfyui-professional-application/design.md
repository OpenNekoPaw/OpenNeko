## Product boundary

The existing Professional Application binding lifecycle owns exact ComfyUI enablement and readiness. Resource owners authorize source content, Generation owns workflow Jobs and verified candidates, Assets owns explicit ingest, and Host performs the exact trusted handoff. ComfyUI remains an external application and does not become an OpenNeko domain authority.

## Core invariants

- An enabled and ready binding does not by itself grant file, API, MCP, or Computer Use authority.
- Every handoff binds an exact application binding, source revision, operation, authorization, and expected outcome.
- Structured API execution and explicitly selected Computer Use are distinct capabilities; failure never switches transport implicitly.
- External outputs become OpenNeko facts only after verification and explicit ingest by the owning resource service.
- Missing bindings, permissions, resources, capabilities, or completion evidence fail visibly and locally.

## Product acceptance

The capability is complete when creators can send supported resources through an enabled ComfyUI binding, observe or cancel the exact Generation Job, and review and explicitly ingest verified outputs through the canonical Desktop path.

## Non-goals

This change does not redefine Professional Application binding management, embed ComfyUI, expose arbitrary process control, or provide generic pixel-coordinate automation.
