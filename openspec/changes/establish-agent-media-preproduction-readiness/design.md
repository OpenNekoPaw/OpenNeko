## Context

OpenNeko 以普通 Agent reasoning 配合领域 Skill 推进媒体创作，Markdown 保存创意与镜头决定，Content、Generation、Canvas 和 Cut 分别保存读取、生成、候选与时间线事实。现有路线强调每轮只完成一个可评审结果，但没有把“单次操作有界”与“整个预处理阶段覆盖充分”区分清楚，导致一次静帧准备后就可能进入视频生成。

## Goals / Non-Goals

**Goals:**

- 让来源分析的画面、人物、剧情、世界观与分镜转译覆盖与方案标题和叙事主张一致。
- 在视频生成前形成覆盖当前制作范围全部计划镜头的素材需求与生成意图，并优先准备可复用的静态参考。
- 让无限定的“继续”留在当前未完成阶段，逐批补齐真实依赖。
- 保持每次生成调用有界、可观察、可失败，不把批量准备变成一个不可检查的大任务。

**Non-Goals:**

- 不建立全局生产状态机、审核关卡、审批记录或预算对象。
- 不规定所有作品必须生成固定数量或固定类别的素材。
- 不让 Agent、Canvas 或 Markdown 接管 Generation Job、媒体文件或 Cut 时间线 authority。
- 不用静态素材数量替代内容覆盖、镜头需要或创作者判断。

## Decisions

### 阶段完成由当前创作事实决定

来源分析以结构、有效正文范围、前中后差异、被选主线的连续因果证据，以及画面、人物、剧情、世界观与分镜转译五类生产相关结论为完成条件。风格抽样只满足画面分析中的局部职责，不能代表完整内容分析。素材预处理以当前制作范围内计划镜头的实际消费需求是否拥有稳定输入、每镜静帧生成／编辑需求是否明确、每镜视频运动意图是否完整为完成条件。PV 的当前制作范围是整支 PV；长篇或 TV 是创作者当前确认的一个剧集、段落或连续制作单元。它们保存在当前创作文档的来源—决定映射、镜头表和逐镜生产输入表中，而不是新的运行时状态。

### 全片覆盖与单次操作分离

素材预处理先逐镜建立当前制作范围的剧情节拍与世界规则、角色状态、物品、场景拓扑、风格、构图、动作和声音需求，再为每镜分别记录静帧生成／编辑意图与视频运动意图，并以多个有界操作逐批满足。已有可直接使用的静帧可以明确不需要图像操作，但仍须绑定真实素材。相同需求可以合并复用，但必须列出全部消费镜头，不能把未分析镜头归为“后续再准备”。单次 Tool 调用仍只消费当前模型和 schema 支持的一组兼容输入；“批量”表示同一阶段连续处理覆盖表中的多个相关缺口，不表示把不同角色、场景和镜头塞进一个不可控请求。

### 静态参考优先于视频候选

优先复用已经验证的来源图像和现有素材；每项素材只按其可观察内容和明确职责满足覆盖，不把单张首帧扩张为人物设定、物品、场景拓扑、动作状态或其他镜头构图。凡镜头表要求且会影响身份、物品、空间拓扑、动作因果、构图或连续性的静态输入，在没有真实等价素材时均为关键缺口。需要新资产时，先准备或生成会被多个镜头消费的角色、物品、场景／世界、风格和关键构图参考，再补齐镜头首帧或关键姿态。默认只有当前制作范围的关键静态素材覆盖没有缺口、全部逐镜生成意图完整，并且当前镜头的身份、状态、空间、物品、起始画面和连续性依赖真实可用时，才把视频生成作为下一操作。单镜首帧就绪或旧文档中的单镜 ready 状态不能绕过其他计划镜头的关键静态素材或提示词缺口；提前试镜只能由创作者明确要求。

### Skill 负责语义编排，领域能力保持原有 authority

Agent Skill 根据 Workspace 事实选择当前阶段和下一操作；Content 负责有界读取，Storyboard/Markdown 承载创意规划，Generation 负责具体图像或视频 Job，Canvas 只投影候选及关系，Cut 负责后期和交付。视频 Tool 不推断全片是否准备充分，Agent 也不以提示词补偿缺失资源或运行时能力。

## Risks / Trade-offs

- **分析或准备无限扩张** → 只保留会改变创意决定或被计划镜头消费的证据和素材，满足当前范围后停止。
- **静态素材生成产生不必要成本** → 优先复用、裁切和整理已有来源；新生成按复用范围和连续性风险排序，并保持每次操作可观察。
- **不同媒体模型支持的批量能力不同** → 每次调用以当前 Tool schema 和模型能力为准，不用工作流规则伪造批量参数。
- **用户明确要求快速试镜** → 可以把它标为有界技术试验，但不得据此宣称素材预处理或整支作品已进入视频生产。
