# Validation Evidence

Date: 2026-07-26

## Real media matrix

Command:

```text
NEKO_FFMPEG_PATH=<qualified-dev-ffmpeg> \
NEKO_FFPROBE_PATH=<qualified-dev-ffprobe> \
pnpm validate:media-matrix ~/Assets/Media
```

The read-only run used FFmpeg/ffprobe 8.1.2 from the explicit development
override. It did not modify or copy user media.

- H.264 720p/AAC 5.1, H.264 video-only, and the small H.264 MP4 produced valid
  probe, five requested frames, direct H.264 preview, and PCM where present.
- AAC and MP3 inputs produced framed PCM.
- AV1 Main 10, PQ/BT.2020, AAC 5.1 produced five requested frames, stereo PCM,
  and an H.264/yuv420p BT.709 proxy. Output contained no HDR side-data block.
- `1080P.mp4` produced a valid first frame, direct-play prefix, and PCM prefix.
  Requests at later advertised timestamps produced `corrupt/interval`; the
  source was not mislabeled as wholly unreadable.
- WebM was listed as skipped under
  `prefer-vscode-playback-formats`, matching the accepted product priority.

## Extension Development Host

Generated fixture workspace:

```text
.tmp/vscode-test-workspaces/media-runtime
```

The fixture was generated by `scripts/prepare-vscode-media-fixture.mjs` and
contains synthetic H.264/AAC, WAV PCM, OTIO, and NKC documents. Validation used
VS Code 1.130.0 / Electron 42.6.0 / Chromium 148.0.7778.280.

- Preview H.264/AAC: metadata rendered and playback reached 0:06.
- Preview WAV/PCM: metadata rendered and playback reached 0:05 of 0:06.
- Cut OTIO: the timeline reached 0:06 through the Node/FFmpeg + MSE + PCM path.
- Canvas audio: placeholder load did not start audio; the explicit Play action
  changed the control to Pause and advanced from 0:00 to 0:01. After the PCM
  HTTP response reached EOF, the player remained at Pause at 0:05 of 0:06 and
  returned to the placeholder only after the final scheduled source ended.
  This proves transport EOF no longer truncates the queued audible tail.
- Canvas video + PCM: placeholder load did not start media; explicit Play
  changed the control to Pause and advanced to 0:02 of 0:06.
- Webview console capture contained no product error. The only entry was
  Chromium's known `local-network-access` feature warning.

Visible host interaction and CDP Webview inspection were both used. A regular
browser was not used as Extension Webview acceptance.

## Streaming waveform validation

Commands:

```text
NEKO_FFMPEG_PATH=<qualified-dev-ffmpeg> \
NEKO_FFPROBE_PATH=<qualified-dev-ffprobe> \
pnpm validate:media-waveform ~/Assets/Media/test.mp3 100

NEKO_FFMPEG_PATH=<qualified-dev-ffmpeg> \
NEKO_FFPROBE_PATH=<qualified-dev-ffprobe> \
pnpm validate:media-waveform ~/Assets/Media/1080P.mp4 100
```

- The complete 226.813-second MP3 produced 22,682 peaks in 301 ms. Node peak
  RSS increased by 26,542,080 bytes and peak ArrayBuffer usage increased by
  13,668,855 bytes; the implementation did not retain the approximately
  43.5 MB complete decoded PCM stream.
- The damaged MP4 advertised 1,795.284 seconds but produced only 139.319 seconds
  of valid audio and 13,932 peaks before AAC corruption. The result retained
  those peaks as `partial/stream`; Node peak RSS increased by 22,872,064 bytes
  and peak ArrayBuffer usage increased by 8,353,100 bytes.
- Unit tests feed samples across non-aligned stream chunks, reject buffered
  FFmpeg execution, preserve a valid prefix after decoder failure, and prove
  cancellation is not converted into partial success.

## Residual release blocker

The explicit development FFmpeg build qualifies the exercised AV1/HDR/AAC
closure, but the repository does not yet stage verified darwin-arm64 and
linux-x64 release payloads with hashes, target metadata, license metadata, and
capability signatures. OpenSpec tasks 4.1–4.3 remain open; packaged activation
must not claim completion or fall back to PATH.
