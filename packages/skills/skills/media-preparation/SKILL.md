# Media Preparation

## 中文方法

先确认当前制作范围的素材与逐镜生成意图覆盖，再为当前优先批次准备下游操作所需的真实输入。状态只属于这一次有界操作：`可提交／未执行`，或存在精确依赖缺口的 `阻塞`；它不代表整个预处理阶段已经完成。

1. 对时间型作品，先读取覆盖当前制作范围的权威镜头表；PV 默认覆盖整支 PV，长篇或 TV 默认覆盖创作者当前确认的一个剧集、段落或连续制作单元。不存在完整镜头范围时返回创意设计或分镜，而不是从第一镜开始猜测生产。独立图片、音频或其他单一素材请求，可以把用户明确指定的当前产物作为完整范围。建立紧凑的逐镜生产输入表：列出每镜的剧情节拍与适用世界规则、角色及状态、物品、场景及空间关系、风格、构图／首尾帧、动作姿态和声音，记录真实来源或精确缺口、预期参考素材、消费镜头、静帧生成／编辑意图状态、视频运动意图状态与当前素材状态。相同需求可以合并一行，但必须列全消费镜头；不得把尚未分析的镜头合并成“后续再准备”。通用标签、提示词描述、未解析路径和旧文档中的 ready 声明不算素材事实。
2. 按复用价值和成本推进：先复用、裁切或整理已验证来源，再准备跨镜复用的角色设定与状态、关键物品、场景／世界拓扑和风格静态锚点，然后准备逐镜分镜构图、动作姿态及首尾帧。参考集合必须足以支撑当前制作范围的身份、剧情因果、世界规则、空间连续性和镜头设计；“有一张氛围图”不等于基础参考完整。生产性视频生成排在这些共享依赖与逐镜生成意图之后。每个现有素材只按可观察内容和绑定职责计入覆盖：一张首帧不能替代角色设定、关键物品、场景拓扑、动作状态和其他镜头构图。凡镜头表要求且会影响身份、物品、空间拓扑、动作因果、构图或连续性的静态输入，没有真实等价素材时就是关键缺口。不同作品不强求固定类别或数量，但关键静态缺口未解决时，必须继续准备静态素材，不能因为某个镜头已有首帧而默认选择视频，也不能把单张静帧、单镜准备包或技术试镜称为预处理完成。
3. 从逐镜生产输入表中选择当前最高优先级的一组兼容素材或逐镜提示词缺口作为一个有界批次。选择前重新以当前镜头表和真实素材计算覆盖；既有单镜输入包或“可提交／未执行”状态只描述原操作，不能作为阶段 authority。当前制作范围仍有关键静态缺口或逐镜生成意图缺口时，默认候选批次不得是视频；只有用户明确要求提前试镜时才允许例外。一个批次可以在当前 schema 明确支持时包含同类多结果；不同角色、场景、媒体类型或不兼容引用拆成后续批次。若一个 `SHxx` 含硬切、蒙太奇或多个独立景别，先回到分镜拆成多个镜头，不能把多镜序列包装成一个可执行单元。时长、比例、运动强度等不会改变故事、角色、交付边界或外部状态的可逆默认值可以明确写出并继续；实质创意选择缺失时阻塞。没有可靠价格能力时，不要求预算估算或预算授权。
4. 绑定精确来源、批次或镜头目标和一个下游生成能力，并读取对应生成 Skill 与当前 Tool schema。若目标包含“先生成静帧，再用该静帧生成视频”等串行依赖，只准备当前已有真实输入支持的最早一次操作；后续操作只能记录依赖与保留约束，不能共享当前状态或交接包。operation、字段名、引用角色和限制只能来自当前 schema。
5. 检查实际素材内容与授权状态，按需完成裁切、去字、蒙版、背景清理、比例统一、关键帧或参考图准备；只有当前能力真实支持时才执行。视频首帧必须是下游可直接消费的单帧素材；带分格、对白、页边或无关画面的漫画原页只能作为来源，不能冒充已准备首帧。无法完成所需预处理时返回缺失的精确操作。
6. 每个参考只承担一个职责：身份、当前状态、空间/构图、风格、运动或声音。写清必须继承与必须忽略的内容。
7. 预处理完成前必须为当前制作范围的每个镜头写清两项生成意图：若需要生成或编辑静帧，提供只描述一个时刻的图像提示词；若已有可直接使用且无需图像操作的真实素材，明确记为“不需要图像操作”并绑定该素材。每镜还必须提供视频运动意图，覆盖起始状态、主体运动、机位运动、环境变化、声音／静音、时长和约束。图像提示词与视频提示词不能合并为一个通用提示词，也不能用镜头摘要或参考标签代替。
8. 逐镜生产输入表可以先保存这些创作意图，但只编译当前一次操作可消费的 prompt 或结构化输入。当前操作是图像生成时，静帧提示词不写时长、镜头运动、转场或连续动作；当前镜头的视频运动意图仍只是后续依赖，不能获得第二个 `可提交／未执行` 状态。当前操作是视频生成时，除非是用户明确要求的提前试镜，否则当前制作范围的关键静态素材覆盖和全部逐镜生成意图必须已经完成；此外还必须存在可直接消费的首帧或起始状态，并且当前镜头所需角色状态、物品、场景空间与连续性参考已经稳定绑定，再按当前 schema 编译该镜的有界视频输入。声音输入同理独立处理，不与图像或视频操作共享状态。
9. 只有真实输入可直接消费且当前 schema 已确认时，才返回 `可提交／未执行`。内部必须按当前 schema 编译完整 Tool 调用封装，并区分顶层 operation、媒体 request operation、必填 wrapper 与稳定输入 locator；实际封装只进入真实 Tool 调用或 owning capability 的结构化对象。默认面向创作者的交接只展示当前批次、稳定素材及职责、可直接使用的提示词或操作意图、预期产物、直接验收、消费镜头，以及逐镜生产输入表中仍未解决的下一批次，不打印 Tool 名、字段名、原始 locator、运行时 ID、参数表或 JSON。只有用户明确要求调试、审计、复现或复制调用时才展示对应技术细节。验收不得放宽上游创意合同中的数值或连续性约束；未执行的调用不得声称已生成或已验证。
10. 缺少真实输入、稳定引用、当前 schema 或实质创意决定时，状态为 `阻塞`。不要生成候选调用包、模拟参数或重复创意分析；只在 Agent 对话中说明一个精确缺口和最小下一动作，保持正式创作文档不被阻塞信息污染。无限定“继续”优先处理逐镜生产输入表中当前阶段的下一批关键缺口，不得跳到视频、后期或交付。用户明确要求提前视频试验时，可以准备该有界操作，但必须标明它不完成预处理覆盖。

“设计完成”“可进入素材预处理”“已有提示词草案”或“一个素材包可提交”都不等于整个预处理阶段完成。面向创作者的交接可以隐藏原始 locator 和 schema 字段，但必须显示可解析的 Workspace 文件、Canvas 节点或已准备资产名称及其职责；只写“参考职责”而没有实际资源，不算绑定。创作文档里的代码样式路径或来源说明只是追踪信息，不自动证明资源引用已经绑定；只有 owning 文档语法可解析的引用、当前操作对象中的稳定绑定，或已物化的 Workspace/Canvas 资产才算真实绑定，不得发明内部选择器的 Markdown 引用语法。只有这个真实资源能被当前下游能力直接消费时，才可称为可执行输入单元。一个素材准备单元不得同时把图像生成和依赖其结果的视频生成标成 `可提交／未执行`。

## English guidance

First inventory material coverage for the authoritative current production range, then prepare real, authorized inputs for the current priority batch and exactly one bounded downstream operation. A PV's range is the whole PV by default; a long-form or TV range is one creator-approved episode, sequence block, or continuous production unit. A state belongs only to one bounded operation: `submit-ready / not executed` or `blocked` with an exact missing dependency; it never completes the whole preparation stage. Return to creative or storyboard work when no complete shot range exists instead of guessing production from the first shot. For a standalone image, audio, or other single-asset request, the creator's explicitly named current artifact may itself define the complete range. The compact per-shot production-input table accounts for the story beat and applicable world rules, character states, objects, environments and spatial relations, style, composition or start/end frames, action poses, and sound, together with real sources or exact gaps, expected reference assets, consumers, still-generation or edit intent status, video-motion intent status, and material status. Identical requirements may share one row only when every consuming shot is named; an unanalyzed range cannot be collapsed into “prepare later.” Generic labels, prompt prose, unresolved paths, and ready claims in old documents are not material facts.

Advance by reuse and cost: reuse, crop, or organize validated source material first; then prepare reusable character designs and states, key objects, environment or world topology, and style anchors; then shot composition, action, and start/end frames. The reference set must support identity, story causality, world rules, spatial continuity, and shot design across the current production range; one atmosphere image is not a complete base package. Count each existing asset only for its observable content and bound role: one first frame cannot replace character sheets, key objects, environment topology, action states, or other shot compositions. A required static input is critical whenever its absence can change identity, objects, spatial topology, action causality, composition, or continuity and no real equivalent asset exists. Production video follows both these shared dependencies and complete per-shot generation intent. While any critical static-material or per-shot generation-intent gap remains, keep preparing the current range: a ready first frame for one shot does not make video the default next operation, and the default eligible batch must not be video. Recompute coverage from the current shot table and real assets; a prior per-shot packet or submit-ready label describes only that operation and has no phase authority. Only an explicitly requested early video test may override that ordering. Select the highest-priority compatible asset or prompt gap as the current bounded batch. A batch may contain multiple same-kind results only when the current schema admits them; split different characters, environments, media kinds, or incompatible references into later batches. One still, packet, or technical shot test does not complete planned-range coverage.

Bind the exact source, batch or shot intent, one downstream Skill, and the current Tool schema. Operation names, fields, reference roles, and limits must come from that schema. If the target contains sequential dependencies such as generating a still and then animating that result, prepare only the earliest operation supported by inputs that already exist. Preserve later constraints only as dependency notes; do not give the later operation the current status or a second submit-ready packet. Unless the creator explicitly requests an early test, a video operation requires complete critical static-material coverage and complete per-shot generation intent for the current production range. It also requires a directly consumable single-frame asset and stably bound character state, objects, environment topology, and continuity references for that shot. A comic page containing panels, dialogue, borders, or unrelated imagery remains source material until an admitted crop, cleanup, or composite operation prepares it. Assign each reference one role—identity, current state, composition, style, motion, or sound—and state what to inherit and ignore. Perform crop, cleanup, masking, normalization, keyframe, or reference creation only through admitted operations. Keep image, video, and sound inputs distinct.

Before preparation completes, every shot in the current production range must record two distinct generation intents. If still generation or editing is needed, its image prompt describes one visual instant—subject, composition, appearance, light/color, reference roles, and constraints—with no duration, camera travel, transition, or changing action sequence. If a real directly usable image already exists and no image operation is intended, mark `no image operation` and bind that asset instead of inventing a prompt. Every shot also needs a video-motion intent covering its starting state, subject motion, camera motion, environmental change, audio or silence, pacing, duration, reference roles, and constraints. A shot summary or generic reference label substitutes for neither intent.

The table may preserve these creative intents for the whole range, but compile only the current operation into schema-specific structured input. One input unit is one continuous generatable take. If a purported `SHxx` contains a hard cut, montage, or multiple distinct framings, return it to Storyboard decomposition rather than packaging it as executable. During an image operation, the same shot's video-motion intent remains a downstream dependency and does not receive a second submit-ready state. During a video operation, require the production-range coverage above plus an existing prepared frame or starting state, then compile only that shot's bounded video input.

When every dependency of the current operation is real and bound, compile that one complete Tool invocation internally and keep it in the actual Tool call or the owning capability's structured object. By default, return a creator-facing semantic handoff containing the current batch, a resolvable Workspace file, Canvas node, or prepared asset name with its role, the current operation's prompt or intent, expected result, direct acceptance, consuming shots, downstream use, and the next unresolved row in the per-shot production-input table. Hiding raw locators and schema fields does not permit replacing the actual resource with a generic “reference role” label. A code-formatted path or source trace in a creative document does not itself prove a bound reference; use only an owning-document reference syntax that resolves, a stable binding in the current operation object, or a materialized Workspace/Canvas asset, and never invent Markdown syntax for an internal selector. “Design complete”, “ready for preparation”, a prompt draft, or one submit-ready packet does not complete preparation; call the bounded unit executable only when the named real resource is directly consumable by the current downstream capability. Never mark both image generation and video generation that depends on its result as submit-ready in one preparation unit. Do not print Tool names, schema fields, raw locators, runtime IDs, parameter tables, or invocation JSON unless the user explicitly asks to debug, audit, reproduce, or copy the call. Preserve upstream numeric and continuity constraints. Never claim an unexecuted request was generated or validated. If a real input, stable locator, current schema, or material decision is missing, do not create a candidate call packet or simulated parameter table. Report one exact blocker and the smallest next action in the Agent conversation, and keep the durable creative document free of blocker narration and speculative handoff content. An unqualified continuation remains on the next critical preparation batch or prompt gap; an explicitly requested early video test may be prepared but stays a technical experiment that does not complete coverage. Do not generate, select, edit, or deliver media.
